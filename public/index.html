04 // KEY COMMANDS
1
Generate SSH Key Pair
WSL
Generate an RSA key pair on the control node for passwordless authentication.
# generate key pair $ ssh-keygen -t rsa -b 4096
2
Copy Public Key to EC2
WSL
Push your public key to both EC2 instances to enable passwordless SSH login.
# copy to webserver $ ssh-copy-id -i ~/.ssh/id_rsa.pub ubuntu@<web-ip>
# copy to dbserver $ ssh-copy-id -i ~/.ssh/id_rsa.pub ubuntu@<db-ip>
3
Test Connectivity
ANSIBLE
Ping all hosts or specific groups to verify the inventory and SSH connectivity.
# ping all nodes $ ansible all -i inventory.ini -m ping
# ping only webservers $ ansible webservers -i inventory.ini -m ping
4
List Inventory Hosts
ANSIBLE
Verify grouping by listing all hosts from the inventory file.
# list all hosts $ ansible-inventory -i inventory.ini --list
# graph view $ ansible-inventory -i inventory.ini --graph
5
Run Ad-Hoc Commands
ANSIBLE
Run one-off commands against a specific group without a playbook.
# check uptime on dbservers $ ansible dbservers -i inventory.ini -m command -a "uptime"
6
Run a Playbook
ANSIBLE
Execute a playbook targeting groups defined in the inventory.
$ ansible-playbook -i inventory.ini playbook.yml
# dry run first $ ansible-playbook -i inventory.ini playbook.yml --check
05 // CONCEPTS COVERED
📋
INVENTORY FILE
Defines all managed nodes in INI format with host variables and group assignments.

SERVER GROUPING
Logical grouping of hosts (webservers, dbservers) to target commands at specific roles.
🔑
PASSWORDLESS SSH
RSA key-pair authentication allowing Ansible to connect without entering a password.
☁️
AWS EC2
Cloud-provisioned Ubuntu instances serving as managed nodes in the Ansible setup.
🐧
WSL
Windows Subsystem for Linux used as the Ansible control node on a Windows machine.
